The hook script receives on stdin a JSON object from Claude Code. Relevant fields:
```json
{
  "session_id": "string — unique per Claude Code session",
  "transcript_path": "string — absolute path to the session transcript JSONL file",
  "stop_hook_active": "boolean — true when Claude is already in a forced-continuation cycle",
  "hook_event_name": "Stop"
}
```

The hook script emits on stdout a JSON object. For a fire (block + reason):
```json
{
  "decision": "block",
  "reason": "Update wiki/inbox/_session.md per .claude/skills/inbox-update/SKILL.md for this turn's work. Skip if only wiki/* files changed."
}
```

For a no-op (allow Claude to stop):
```json
{}
```
or just `exit 0` with no stdout (Claude Code treats empty stdout as allow-stop).

The .claude/settings.json Stop hook schema:
```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/inbox-stop.sh",
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

The fire-counter file format (.claude/inbox/.fire-counter):
```
<turn_id> <count>
```
where turn_id is derived from the current session_id + a timestamp boundary (minute granularity
is sufficient to define "same turn"). The counter caps at 2 and resets on a new turn boundary.

Transcript JSONL format (excerpt — what the pre-filter needs):
Each line is a JSON object. Tool calls appear as messages with role "assistant" and content
arrays containing objects with type "tool_use". Tool names to look for: "Edit", "Write",
"MultiEdit". Grep-scanning is sufficient — no full parse needed.

The inbox-update skill path (canonical, absolute within the project):
  .claude/skills/inbox-update/SKILL.md

Kill switch file: .claude/inbox/.disabled  (presence = disabled, absence = active)
Heartbeat log file: .claude/inbox/.hook-log  (append-only)
Fire counter file: .claude/inbox/.fire-counter

Create a new directory .claude/hooks/ if it does not exist, then write the hook script.
The script must implement all seven behaviors in this exact order:

**Step 1 — Read stdin:**
```bash
INPUT=$(cat)
```

**Step 2 — Unconditional heartbeat (D-04):**
Write a line to .claude/inbox/.hook-log BEFORE any guards. Format:
```
<ISO-8601 timestamp> <session_id> entering
```
Extract session_id from INPUT using grep/sed (look for "session_id"). If extraction fails,
use "unknown". Use `>> "$CLAUDE_PROJECT_DIR/.claude/inbox/.hook-log"` (append, absolute path via
CLAUDE_PROJECT_DIR per D-12). Create the file if absent (the >> operator does this automatically).
This line proves the hook fired even if it exits early.

**Step 3 — stop_hook_active guard (D-01):**
Parse INPUT for `"stop_hook_active"` field. Use bash string matching or grep:
```bash
if echo "$INPUT" | grep -q '"stop_hook_active"[[:space:]]*:[[:space:]]*true'; then
  log_outcome "stop-hook-active"
  exit 0
fi
```
Write a second heartbeat line with outcome "stop-hook-active" before exiting.

**Step 4 — Kill switch guard (D-02):**
```bash
if [ -f "$CLAUDE_PROJECT_DIR/.claude/inbox/.disabled" ]; then
  log_outcome "kill-switch"
  exit 0
fi
```

**Step 5 — Hard cap guard (D-03):**
Check .claude/inbox/.fire-counter. The counter file contains a single line:
`<turn_key> <count>` where turn_key = session_id + current minute (date +%Y%m%d%H%M).
- Read the file if it exists.
- If the stored turn_key matches the current turn_key AND count >= 2: log "hard-cap", exit 0.
- If the stored turn_key matches AND count < 2: increment count and write back.
- If the stored turn_key does not match (new turn): write `<turn_key> 1` (first fire).
Use $CLAUDE_PROJECT_DIR/.claude/inbox/.fire-counter as the path (absolute, per D-12).

**Step 6 — Transcript pre-filter (D-05):**
Extract transcript_path from INPUT:
```bash
TRANSCRIPT=$(echo "$INPUT" | grep -o '"transcript_path"[[:space:]]*:[[:space:]]*"[^"]*"' | grep -o '"[^"]*"$' | tr -d '"')
```
If TRANSCRIPT is non-empty and the file exists, scan it for tool-call presence:
```bash
if [ -n "$TRANSCRIPT" ] && [ -f "$TRANSCRIPT" ]; then
  if ! grep -q '"name"[[:space:]]*:[[:space:]]*"\(Edit\|Write\|MultiEdit\)"' "$TRANSCRIPT" 2>/dev/null; then
    log_outcome "noop"
    exit 0
  fi
fi
```
If transcript_path is absent or the file doesn't exist, fall through (safe default: fire).

**Step 7 — Emit decision:block + reason (D-10):**
```bash
REASON="Update wiki/inbox/_session.md per .claude/skills/inbox-update/SKILL.md for this turn's work. Skip if only wiki/* files changed."
printf '{"decision":"block","reason":"%s"}\n' "$REASON"
log_outcome "fire"
```
The reason string must:
- Be under 200 chars (count it — the example above is ~151 chars)
- Reference .claude/skills/inbox-update/SKILL.md (per D-06)
- Include "Skip if only wiki/* files changed" (per D-08)

**Helper function log_outcome:**
Define at the top of the script:
```bash
log_outcome() {
  local OUTCOME="$1"
  local TS
  TS=$(date -u +%Y-%m-%dT%H:%M:%SZ 2>/dev/null || date +%Y-%m-%dT%H:%M:%SZ)
  echo "$TS ${SESSION_ID:-unknown} $OUTCOME" >> "$CLAUDE_PROJECT_DIR/.claude/inbox/.hook-log"
}
```

**Script header:**
```bash
#!/usr/bin/env bash
set -euo pipefail
```

**After writing:** `chmod +x .claude/hooks/inbox-stop.sh`

**Do NOT:**
- Use `additionalContext` (per D-10, locked Phase 1 — this mechanism is silently dropped on Stop hooks)
- Use `decision:"block"` without reason (reason is what delivers the skill nudge)
- Use relative paths anywhere — always `$CLAUDE_PROJECT_DIR/...`
- Add `SubagentStop` to settings.json (D-07 strict)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude Code → hook script stdin | Hook receives Stop event JSON from Claude Code process; single-user, local process |
| Hook script → stdout | Hook emits JSON decision back to Claude Code; must be well-formed |
| Hook script → filesystem | Hook appends to .hook-log, reads/writes .fire-counter, checks .disabled |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Denial of Service | Infinite loop via decision:"block" | mitigate | D-01 stop_hook_active check exits 0 immediately on re-entry; D-03 hard cap of 2 fires per turn keyed by session_id+minute; D-02 kill switch .claude/inbox/.disabled lets user escape |
| T-03-02 | Elevation of Privilege | Script execution with broad shell access | accept | Hook is a small auditable bash script (~60 lines) with no network calls; reads only transcript and writes only to .claude/inbox/ scoped files; sole-developer tooling per PROJECT.md |
| T-03-03 | Tampering | Path traversal via computed CLAUDE_PROJECT_DIR paths | mitigate | D-12 uses $CLAUDE_PROJECT_DIR (provided by Claude Code, not user-controlled); all paths are constructed as "$CLAUDE_PROJECT_DIR/.claude/inbox/..." — no user input interpolated into paths |
| T-03-04 | Information Disclosure | Transcript read exposes non-source content | accept | Transcript is already in Claude Code's own process space; the hook only grep-scans for tool names, does not log content; no secrets are extracted |
| T-03-05 | Denial of Service | Unbounded .hook-log file growth | accept | HARD-01 (log rotation) deferred to Phase 5 per CONTEXT.md deferred items; for v1 single-developer sessions this is low risk |
| T-03-06 | Tampering | .fire-counter race condition across concurrent sessions | accept | HARD-01 concurrent-session safety deferred; Phase 3 assumes single-session per PROJECT.md single-developer scope; worst case: a concurrent session resets the counter and the cap fires one extra time |
</threat_model>
