**Turn A — work-bearing turn (function add):**
Ask Claude to add a small helper function. Example prompt:
  "Add a function `clamp(value, min, max)` to tests/fixtures/math.ts that returns value
  clamped to [min, max]. One-liner implementation."

Expected results:
  - Claude writes the function (Edit/Write tool call on tests/fixtures/math.ts)
  - Claude's turn ends → Stop hook fires → Claude is nudged to run /inbox-update
  - Claude runs the inbox-update skill
  - wiki/inbox/_session.md gains an entry like:
      `@ FUNCTIONS::clamp  •  tests/fixtures/math.ts  •  #function #math`
  - .claude/inbox/.hook-log gains a "fire" line for this turn

Verify after Turn A:
```bash
grep -c "^@ " wiki/inbox/_session.md   # should be 1
tail -5 .claude/inbox/.hook-log          # should show "fire" for this turn
```

**Turn B — work-bearing turn (function delete):**
Ask Claude to delete the function just added. Example prompt:
  "Delete the clamp function from tests/fixtures/math.ts."

Expected results:
  - Claude deletes the function
  - Stop hook fires → inbox-update runs
  - The FUNCTIONS::clamp entry is pruned from wiki/inbox/_session.md
  - wiki/inbox/_session.md returns to zero entries
  - .hook-log gains another "fire" line

Verify after Turn B:
```bash
grep -c "^@ " wiki/inbox/_session.md   # should be 0
tail -5 .claude/inbox/.hook-log          # should show second "fire"
```

**Turn C — pure-conversation turn (no tool calls):**
Ask a question that requires no file edits. Example prompt:
  "What is the purpose of the wiki/inbox/_session.md file?"

Expected results:
  - Claude answers in text only (no Edit/Write/MultiEdit tool calls)
  - Stop hook fires → transcript pre-filter detects no tool calls → exits 0 (noop)
  - wiki/inbox/_session.md remains at zero entries (no mutation)
  - .hook-log gains a "noop" line (not "fire")

Verify after Turn C:
```bash
grep -c "^@ " wiki/inbox/_session.md   # still 0
tail -5 .claude/inbox/.hook-log          # should show "noop" (not "fire")
```

**Turn D — loop protection check:**
Review the .hook-log for Turn A (the work-bearing turn). Confirm:
```bash
grep "fire\|stop-hook-active\|hard-cap" .claude/inbox/.hook-log
```
The log should show at most 2 "fire" lines per turn (same session_id + minute).
There should be NO "stop-hook-active" lines (that would indicate forced-continuation
was still being triggered — a potential loop).

**Turn E — full log review:**
```bash
cat .claude/inbox/.hook-log
```
The log should show: one "entering" + one outcome per hook invocation. Outcomes should be:
fire, fire (A twice if re-triggered), noop (C). No outcome should repeat more than 2 times
for any single turn.
