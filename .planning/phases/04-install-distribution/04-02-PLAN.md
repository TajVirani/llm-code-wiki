Required sections and content:

**Title:** `# llm-code-wiki`

**Section: What this is (2-3 sentences)**
Brief description: Claude Code skill + hook scaffolding that auto-maintains an Obsidian-style wiki. Stop hook fires after each work-bearing turn; `/digest` consolidates the session inbox into filed notes per `wiki/Rules.md`.

**Section: Prerequisites**
- Claude Code (current generation with skills + hooks support)
- `jq` (required only if `.claude/settings.json` already exists with content — see Installation)
- `CLAUDE_CODE_FORK_SUBAGENT=1` environment variable if the `/digest` sub-agent fork path is used (set in shell profile or `.env`; without it, `context: fork` in the digest skill may fall back to inline execution — the non-fork fallback at `.claude/skills/digest/reference/non-fork-fallback.md` covers this case)
- Bash 4+ (macOS ships bash 3; upgrade via `brew install bash` or use the non-fork fallback which avoids bash version sensitivity)

**Section: Installation**
1. Copy the `.claude/` tree from this repo into the target project (plugin, marketplace, manual copy, or symlink — method is your choice; the `.claude/` tree is the distribution unit)
2. Start a Claude Code session in the target project
3. Run `/wiki-install` — it bootstraps `wiki/`, merges the hook entry into `.claude/settings.json`, and appends a discovery section to `CLAUDE.md`
4. Restart Claude Code (required once, so it picks up the new `.claude/skills/wiki-install/` directory that was just added)
5. Take any work-bearing turn (write or edit a file) — the inbox updates automatically

Note: if you already have content in `.claude/settings.json`, `jq` must be installed for the merge step. Without jq, `/wiki-install` aborts and points you to `wiki/_templates/SETTINGS-SNIPPET.md` for manual merge instructions.

**Section: Known interactions**
- `disableSkillShellExecution: true` in Claude Code settings breaks the digest skill's bash injections (Steps 1/3 in the digest skill become empty strings). The skill's fallback — using the Read tool directly — still works, but performance degrades. Recommendation: keep shell execution enabled.
- If you already have a `Stop` hook registered, `/wiki-install` will NOT overwrite it. The wiki inbox-stop hook is added alongside your existing hook in the `hooks.Stop[0].hooks` array. If you have a hook that sets `stop_hook_active: true`, this may suppress the inbox-update nudge — intentionally, per the loop-protection design.
- The wiki-curator sub-agent name (`wiki-curator`) must not collide with an existing sub-agent of the same name in `.claude/agents/`. If a collision exists, the consumer's project-scope agent wins by Claude Code precedence rules — rename one.

**Section: Anti-features (things this system does NOT do)**
Be explicit; these are documented intentionally so users have correct expectations:
- No real-time wiki sync as code changes (hooks cannot write files mid-turn; the inbox captures per-turn summaries)
- No auto-digest (digest is a manual, review-gated checkpoint — you decide when entries get filed)
- No backfill from existing code (this tool captures what Claude builds going forward; it does not summarize an existing codebase)
- No `/reconcile` skill in v1 (wiki↔codebase reconciliation — checking that filed notes still match the live code — is deferred to v2 as HARD-03)
- No modification of `wiki/Rules.md` autonomously (rule-change suggestions from the curator surface as proposals for the user to apply; the curator never edits Rules.md)
- No multi-user safety (concurrent sessions may race on `wiki/inbox/_session.md`; per-session inbox isolation is deferred to v2 as HARD-01)

**Section: Usage**
- **Inbox updates:** automatic on every work-bearing turn (Stop hook fires, inbox-update skill is nudged)
- **Digest:** run `/digest` at a review checkpoint to file inbox entries into wiki notes
- **Wiki contract:** edit `wiki/Rules.md` to customize categories, filename conventions, and note shape — the curator respects whatever Rules.md says
- **Hook audit:** `.claude/inbox/.hook-log` shows every hook fire with timestamp and outcome (entering/fire/noop/kill-switch/etc.)
- **Kill switch:** `touch .claude/inbox/.disabled` disables the Stop hook without editing `settings.json`; `rm .claude/inbox/.disabled` re-enables

**Section: File layout**
```
wiki/
  Rules.md                  # Wiki conventions contract (edit freely)
  _templates/
    note.md                 # Canonical note template
    SETTINGS-SNIPPET.md     # Manual hook-entry fallback (for jq-absent installs)
  inbox/
    _session.md             # Rolling session inbox (auto-updated by hook)
    _archive/               # Timestamped inbox snapshots (created by /digest)
  ARCHITECTURE/             # Filed notes by category (created by /digest)
  FUNCTIONS/
  RESEARCH/
  SELF/
  DIAGRAMS/                 # Optional — create only when needed

.claude/
  skills/
    wiki-install/SKILL.md   # /wiki-install bootstrap command
    inbox-update/SKILL.md   # /inbox-update in-session skill (nudged by hook)
    digest/SKILL.md         # /digest consolidation command
    wiki-rules/SKILL.md     # Rules contract carrier (preloaded by curator)
  agents/
    wiki-curator.md         # Digest sub-agent
  hooks/
    inbox-stop.sh           # Stop hook script
  inbox/
    .hook-log               # Hook audit log
    .fire-counter           # Per-turn fire counter (loop protection)
```

```bash
cat > /tmp/wiki-install-test-target/verify-install.sh << 'SCRIPT'
#!/usr/bin/env bash
# verify-install.sh — Run after each /wiki-install invocation
# Usage: bash /tmp/wiki-install-test-target/verify-install.sh [run1|run2]
set -euo pipefail
TARGET="/tmp/wiki-install-test-target"
RUN="${1:-run1}"

echo ""
echo "=== wiki-install verification: $RUN ==="
echo ""

PASS=0
FAIL=0

check() {
  local DESC="$1"
  local CMD="$2"
  if eval "$CMD" >/dev/null 2>&1; then
    echo "  PASS: $DESC"
    PASS=$((PASS+1))
  else
    echo "  FAIL: $DESC"
    FAIL=$((FAIL+1))
  fi
}

# Deliverable 1: wiki/ directory
check "wiki/ directory exists" "test -d '$TARGET/wiki'"

# Deliverable 2: wiki/_templates/note.md
check "wiki/_templates/note.md exists" "test -f '$TARGET/wiki/_templates/note.md'"

# Deliverable 3: wiki/Rules.md
check "wiki/Rules.md exists" "test -f '$TARGET/wiki/Rules.md'"

# Deliverable 4: wiki/inbox/ directory
check "wiki/inbox/ directory exists" "test -d '$TARGET/wiki/inbox'"

# Deliverable 5: settings.json with inbox-stop.sh entry
check ".claude/settings.json exists" "test -f '$TARGET/.claude/settings.json'"
check "settings.json contains inbox-stop.sh" "grep -q 'inbox-stop.sh' '$TARGET/.claude/settings.json'"

# Deliverable 6: CLAUDE.md with Auto-maintained wiki section
check "CLAUDE.md exists" "test -f '$TARGET/CLAUDE.md'"
check "CLAUDE.md has Auto-maintained wiki section" "grep -q '## Auto-maintained wiki' '$TARGET/CLAUDE.md'"

# Run 2 only: idempotency — check second run produces skip messages
if [ "$RUN" = "run2" ]; then
  echo ""
  echo "=== Idempotency checks (run2) ==="
  echo "  Manual check required: review the /wiki-install output above."
  echo "  Every deliverable line should say 'skipping' or 'already exists'."
  echo "  Expected skip messages:"
  echo "    [wiki-install] wiki/ already exists, skipping"
  echo "    [wiki-install] wiki/_templates/note.md already exists, skipping"
  echo "    [wiki-install] wiki/Rules.md already exists, skipping"
  echo "    [wiki-install] wiki/inbox/ already exists, skipping"
  echo "    [wiki-install] Stop hook already registered in settings.json, skipping"
  echo "    [wiki-install] CLAUDE.md already documents auto-wiki, skipping"
fi

echo ""
echo "=== Results: $PASS passed, $FAIL failed ==="
if [ "$FAIL" -eq 0 ]; then
  echo "  ALL CHECKS PASS"
else
  echo "  FAILURES DETECTED — review above"
fi
SCRIPT
chmod +x /tmp/wiki-install-test-target/verify-install.sh
```
