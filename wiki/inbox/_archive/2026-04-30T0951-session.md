@ ARCHITECTURE::stop-hook-self-heals-runtime-dir  •  .claude/hooks/inbox-stop.sh  •  #hook #install #robustness
The Stop hook script `mkdir -p`s `.claude/inbox/` at startup so heartbeat / fire-counter / kill-switch writes succeed on a fresh install. Without this, `wiki-install`'s smoke test fails on any project that hasn't had the runtime dir pre-created elsewhere.

@ ARCHITECTURE::recall-path  •  —  •  #recall #hook #architecture
A UserPromptSubmit hook detects planning-intent prompts and asks Claude to consult the wiki via the `wiki-recall` sub-agent before responding. The agent uses `wiki/topic-index.md` as a navigation map, greps for keywords, applies a relevance filter, and returns a compact context payload. `/recall` is the manual equivalent. Mirrors the capture path (Stop hook + inbox + `/wiki-digest`) but for reads.

@ FUNCTIONS::recall-prompt-hook  •  .claude/hooks/recall-prompt.sh  •  #hook #recall #script
UserPromptSubmit hook. Pre-filters prompts for planning-intent keywords (plan, design, implement, refactor, etc.), skips wiki-only prompts (digest, /recall, inbox), respects a kill switch (`.claude/inbox/.recall-disabled`), and applies a session+prompt-hash cooldown to prevent double-fire. On match, emits a stdout block instructing Claude to spawn the wiki-recall sub-agent.

@ ARCHITECTURE::wiki-recall-subagent  •  .claude/agents/wiki-recall.md  •  #agent #recall #read-only
Read-only sub-agent (Read/Glob/Grep only — no Write/Edit). Reads `wiki/topic-index.md` first as a navigation map, extracts 3–8 keywords from the task, builds a primary candidate set from index bullets, then greps `wiki/` for additional hits. Applies a relevance filter (drops superficial overlap, `#deprecated`, superseded, or stub notes) and returns a ≤400-word summary citing notes by `[[Title]]`.

@ FUNCTIONS::recall-skill  •  .claude/skills/recall/SKILL.md  •  #skill #recall #command
The `/recall` slash command. Forks into the `wiki-recall` sub-agent via `context: fork`. Accepts an optional query argument; defaults to the current conversation context. Surfaces the agent's return verbatim. Used when the recall hook didn't fire (non-planning phrasing) or for focused on-demand recall.

@ ARCHITECTURE::topic-index-as-recall-map  •  wiki/topic-index.md  •  #recall #index #navigation
Flat greppable bullet list. Each bullet: bold topic name (kebab-case), ≤25-word summary describing what the topic covers, and a comma-separated list of relative file paths from `wiki/` root. No `[[wiki-link]]` syntax — explicit paths so grep returns precise hits. Auto-maintained by the curator's Step 9 at the end of every `/wiki-digest`. Hard cap: 100 entries.

@ ARCHITECTURE::curator-step-9-index-update  •  .claude/agents/wiki-curator.md  •  #curator #digest #index
The `wiki-curator` protocol has a Step 9 that runs after the post-write link audit: it updates `wiki/topic-index.md` to reflect newly created, edited, split, or deprecated notes. Bullets are appended preserving existing summaries unless scope materially expanded, deduped, and alphabetized; `Last Updated` is bumped. Only topics affected by the digest are touched.

@ ARCHITECTURE::skill-naming-wiki-prefix  •  —  •  #skill #convention #naming
Skills and slash commands that operate on the wiki use a `wiki-` prefix: `/wiki-install`, `/wiki-digest`, plus the `wiki-rules` skill. The `inbox-update` and `recall` skills are exceptions for now — `inbox-update` is invoked only by the Stop hook (no slash command) and `recall` would collide with the `wiki-recall` agent name if renamed. The convention is that user-facing wiki commands take the prefix.

@ RESEARCH::skill-bash-injection-isolation  •  .claude/skills/wiki-digest/SKILL.md  •  #skill #bash #pattern
Claude Code's `!`-prefixed bash injections in skill bodies do NOT share shell state across blocks — each `!`...`!` invocation is an independent shell. Variables set in one block (e.g. `INBOX_PATH=...` described in surrounding prose) are not visible to subsequent blocks. The pattern: every block that needs a derived value must compute it inline. The `wiki-digest` skill resolves the inbox path as `P="${ARGUMENTS:-wiki/inbox/_session.md}"` at the top of each of its three bash injections. Prose-level descriptions of variable resolution are documentation only — they do not affect runtime.
