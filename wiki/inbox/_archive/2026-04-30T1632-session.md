@ RESEARCH::replace-all-rename-substring-trap  •  —  •  #refactor #rename #pattern
When renaming a slash command or skill via global `replace_all "/X" → "/wiki-X"` (or similar), file paths and filenames that contain the rename target as a substring get silently rewritten too. Concrete instance: `replace_all "/recall" → "/wiki-recall"` rewrote `.claude/hooks/recall-prompt.sh` references to `.claude/hooks/wiki-recall-prompt.sh` even though the script was deliberately not renamed (internal scaffolding keeps its original name). Symptom appears later as install-time ABORT or runtime path-not-found. Mitigation: after a global rename, audit referenced paths against the actual filesystem (`grep -roE '\.claude/[a-z/]+\.sh' | xargs -I{} test -f {}`) and verify no `<old>-<word>.<ext>` artifacts where `<old>` is the rename target.

@ FUNCTIONS::inbox-stop-hook  •  .claude/hooks/inbox-stop.sh  •  #hook #capture #brainstorm
Stop hook fired at every assistant turn boundary. Loop-protection trifecta D-01 (stop_hook_active), D-02 (kill switch `.claude/inbox/.disabled`), D-03 (hard cap of 2 actual fires per session+minute, counter at `.claude/inbox/.fire-counter` — only bumped on real fires, not noops). Maintains a per-session brainstorm counter at `.claude/inbox/.turn-count` (`SESSION_ID COUNT`). Step 8 branches three ways: artifact present (Edit/Write/MultiEdit in transcript) → fire normal capture and reset brainstorm counter; no artifact AND counter ≥ N → fire brainstorm-fallback with a different reason payload, then reset counter; otherwise log `turncount-pending COUNT/N` and exit. N defaults to 10, override via `LCW_BRAINSTORM_TURNS` env var (rejects non-integer / <1 values, defaults to 10). Hook-log outcomes: `entering`, `stop-hook-active`, `kill-switch`, `hard-cap`, `fire turncount-reset-on-artifact`, `turncount-fire COUNT/N`, `turncount-pending COUNT/N`.

@ RESEARCH::brainstorm-fallback-cadence  •  —  •  #decision #brainstorm #hooks
Default cadence for the brainstorm-fallback capture path is 10 turns, configurable via `LCW_BRAINSTORM_TURNS` env var. Counter reset semantics: resets to 0 whenever a normal artifact-driven capture fires, so each brainstorm window starts fresh after a code change (avoids redundant capture immediately after a real fire). Counter is keyed by `SESSION_ID`, so a new session starts the count over automatically. Cap is ≤5 new entries per fallback fire to avoid overloading `_session.md` during long brainstorms. Hard-cap (2 fires/minute) was refactored to count only actual fires, not entries — otherwise a long brainstorm in a single minute would consume the cap on noops and never reach the fallback fire. Documented in `CLAUDE.md` under "Auto-maintained wiki".

@ ARCHITECTURE::remote-install-flow  •  dist-manifest.txt  •  #install #distribution #architecture
Remote-install flow lets a user point Claude at the public repo URL and have the scaffold fetched into the target project without dragging the source repo's dogfood wiki along. `dist-manifest.txt` at the repo root is the authoritative list of distribution paths (16 entries: `VERSION`, `CHANGELOG.md`, 8 skill files, 2 agents, 2 hooks, `wiki/Rules.md`, `wiki/_templates/note.md`). Each manifest line is optionally whitespace-separated `PATH [POLICY]` where POLICY defaults to `overwrite`; `keep` is used for `wiki/Rules.md` and `wiki/_templates/note.md` so user customizations are preserved on update. `.claude/settings.json` is deliberately excluded from the manifest — `/wiki-install` Step 5/5b handles hook registration via merge instead of overwrite (and `/wiki-update` re-runs the same merge). `CLAUDE.md` is also excluded; its `## Auto-maintained wiki` section is owned by `/wiki-install` Step 6 and refreshed by `/wiki-update`. `wiki/topic-index.md` is excluded because this repo's copy contains dogfood bullets, not the canonical empty seed; the empty seed is inlined in `wiki-install/SKILL.md` Step 4b instead. `INSTALL.md` "Remote install — for Claude" section gives Claude an executable recipe: derive raw base URL from the repo URL, fetch manifest, fetch each listed file (skip-if-exists for the two `keep`-policy seeds), `chmod +x` hooks, then read the just-fetched `wiki-install/SKILL.md` and execute Steps 0–7b directly (the `/wiki-install` slash command isn't registered yet — only registers on next Claude restart). Existing copy-files install path is preserved as "Manual install (alternative)". `README.md` Quick Start leads with the remote one-liner. Hooks are live after install without restart; only slash commands require a restart.

@ FUNCTIONS::wiki-install-skill  •  .claude/skills/wiki-install/SKILL.md  •  #skill #install #bootstrap
`/wiki-install` slash command bootstraps the auto-wiki system in a target project. Step 0 precondition check verifies all required `.claude/` files are present and both hooks are executable; aborts with a clear pointer if anything is missing. Steps 1–4b idempotently create `wiki/`, `wiki/_templates/note.md`, `wiki/Rules.md`, `wiki/inbox/`, and `wiki/topic-index.md` (skip-if-exists; never overwrites user content). Step 3 (Rules.md) has a partial-install guard — if the file is absent and source repo isn't accessible, abort with a pointer to `INSTALL.md` "Remote install" or `dist-manifest.txt`. Step 4b (topic-index.md) contains the full canonical empty seed inline — front-matter, HTML maintenance comment, and a `Related Notes` link to `[[Rules]]` — because `topic-index.md` isn't shipped via the distribution manifest. Step 5/5b merges Stop and UserPromptSubmit hook entries into `.claude/settings.json` using three-case logic (Case A: file absent → write canonical full structure; Case B: hook already registered → skip; Case C: needs merge → use jq with `--arg` so the literal `$CLAUDE_PROJECT_DIR` token survives, then verify post-merge). Step 6 appends an "Auto-maintained wiki" section to `CLAUDE.md` (or creates the file) — the markdown code-fenced block at this step is the **canonical source of truth** for the section's content (extracted by `/wiki-update` Step 6 to refresh CLAUDE.md without divergence). Step 7 runs three smoke tests: Stop hook fires (heartbeat in `.hook-log` for synthetic session ID), recall hook fires (`recall:fire` log entry plus `Wiki recall` block in stdout), inbox writability. Step 7b copies `VERSION` to `.claude/llm-code-wiki.version` so `/wiki-update` has a baseline to compare against; if `VERSION` is absent (manual install from old checkout), warns and skips — `/wiki-update` treats a missing stamp as `0.0.0`. Every step prints a `[wiki-install] …` progress line; no step is silent. Idempotent — re-running after partial install is safe.

@ FUNCTIONS::wiki-digest-skill  •  .claude/skills/wiki-digest/SKILL.md  •  #skill #digest #lifecycle
`/wiki-digest` consolidates inbox sources into filed wiki notes via the wiki-curator subagent. Owns the lifecycle around the curator's writes: source discovery, archive-before-write, post-write link audit, source-file deletion on success, no-op path. Step 1 discovers TWO source types — `wiki/inbox/_session.md` (handle-line entries) and any user-dropped `.md` file in `wiki/inbox/` excluding `_session.md` and underscore-prefixed files (free-prose research docs). Combined no-op guard skips only when both sources are empty. Step 2 archives every source to `wiki/inbox/_archive/<TS>-session.md` and `<TS>-research-<filename>.md` with one shared timestamp before any note write (LIFE-03 crash-safety). Step 3 emits a delimited research-doc payload (`=== RESEARCH-DOC: <path> === … === END RESEARCH-DOC ===`) alongside session content, the wiki tree, and Rules.md to the curator. Step 6a resets `_session.md` on success; Step 6b deletes consumed research-doc source files only when every derived concept was APPLIED, preserves on unresolved CONFLICT-ON-RESEARCH or apply error. Step 7 emits a digest summary grouped by source.

@ FUNCTIONS::wiki-curator-agent  •  .claude/agents/wiki-curator.md  •  #agent #digest #routing
Curator subagent consumed by `/wiki-digest`. Routes both session-inbox handle-line entries AND research-doc free-prose markdown into filed wiki notes per Rules.md. For research docs, applies Rules.md §6 to derive {slug, title, category, tags, summary} per concept (single-concept → 1 note; multi-concept → N notes), each becoming a virtual entry that joins the routing pipeline. Same-concept detection (filename + title + tag overlap, never embeddings — A10) drives EDIT vs CREATE. D-19 RESEARCH/ write-protection branches by source: session-inbox hits emit ALERT rows (curator routes to handle's category, never writes RESEARCH/); research-doc hits emit CONFLICT-ON-RESEARCH rows that defer to Step 7a interactive resolution where the user picks "replace" / "append" / "skip" / free-form per conflict before any write to RESEARCH/. Plan groups rows by source under `## Source: <path>` sub-headings. Plan-level approval (D-03) covers CREATE/EDIT/SPLIT/OVERRIDE only; CONFLICT-ON-RESEARCH explicitly excluded. Curator does not delete research-doc source files — that's owned by wiki-digest skill body Step 6b.

@ ARCHITECTURE::research-doc-ingestion  •  —  •  #architecture #digest #ingestion
Lifecycle for ingesting user-dropped `.md` research docs into the wiki. User drops any `.md` file (other than `_session.md` and underscore-prefixed) into the root of `wiki/inbox/`. On the next `/wiki-digest` run: skill body discovers the docs, archives each to `wiki/inbox/_archive/<TS>-research-<filename>.md`, passes a delimited payload to the curator; curator decomposes each doc into one or more concept notes (Rules.md §6), validates per Rules.md, applies CREATE/EDIT/SPLIT/OVERRIDE rows from a source-grouped plan, surfaces CONFLICT-ON-RESEARCH for any collision with existing read-only `wiki/RESEARCH/` notes (interactive resolution in Step 7a — replace / append / skip / free-form). On success, skill body deletes consumed source files from `wiki/inbox/`; preserves any whose concepts had unresolved conflicts. Documented in CLAUDE.md, INSTALL.md, and wiki/Rules.md §6/§9.

@ ARCHITECTURE::update-flow  •  .claude/skills/wiki-update/SKILL.md  •  #architecture #update #versioning #distribution
End-to-end versioning + upstream update mechanism for projects that installed the scaffold. Source-of-truth version lives in `VERSION` at repo root (single-line semver, currently `1.0.0`). `CHANGELOG.md` follows Keep-a-Changelog format with a `### Migration` subsection per release listing manual steps `/wiki-update` cannot perform. Installs stamp the upstream version into `.claude/llm-code-wiki.version` (written by `/wiki-install` Step 7b) so `/wiki-update` has a baseline. `dist-manifest.txt` extended with optional whitespace-separated policy column: `overwrite` (default — fetch + replace) or `keep` (skip if local exists; notify when upstream differs). `wiki/Rules.md` and `wiki/_templates/note.md` use `keep`; `wiki/topic-index.md` stays out of the manifest entirely (curator regenerates it). `.claude/settings.json` and `CLAUDE.md` are also outside the manifest and instead handled directly by `/wiki-update` Steps 5–6: settings.json upserts the two hook entries by command-substring (`inbox-stop.sh`, `recall-prompt.sh`), preserving unrelated hooks/permissions/env/MCP servers; CLAUDE.md replaces only the `## Auto-maintained wiki` section, sourcing canonical content from the just-updated `wiki-install/SKILL.md` Step 6 markdown block (single source of truth, kept in sync with the rich live content). Version stamp updates only after every step succeeds, so a failed update is safely re-runnable.

@ FUNCTIONS::wiki-update-skill  •  .claude/skills/wiki-update/SKILL.md  •  #skill #update #versioning #lifecycle
`/wiki-update` slash command pulls upstream scaffold improvements into an existing install. Optional argument `/wiki-update <RAW_BASE>` overrides the default upstream for forks/branches. Step 0 aborts if `.claude/skills/wiki-install/SKILL.md` is missing (proxy for "scaffold installed"). Step 1 reads local `.claude/llm-code-wiki.version` (defaults `0.0.0` if absent), fetches upstream `VERSION`, compares with `sort -V`; equal/newer-local exits as no-op. Step 2 fetches `CHANGELOG.md` and slices sections strictly between local (exclusive) and upstream (inclusive) using awk semver compare, displays them, and asks the user `Apply this update? (yes/no)` in plain text — confirmation is conversational, not a tool dialog, so the user can push back before commit. Step 3 fetches `dist-manifest.txt`. Step 4 loops manifest applying per-line policy: `overwrite` mkdirs + curls + `chmod +x` for `.sh` paths; `keep` cmps local vs upstream tmp file, building a manual-review list with github.com diff URLs (raw → blob URL conversion via sed) when they differ. Step 5 re-merges `.claude/settings.json` Stop + UserPromptSubmit entries by command-substring — defensively removes matches then appends canonical entries, preserving permissions/env/MCP servers/unrelated hooks; aborts if jq is absent (same constraint as wiki-install) and verifies post-merge that the literal `$CLAUDE_PROJECT_DIR` token survived. Step 6 extracts the canonical `## Auto-maintained wiki` block from the just-updated `wiki-install/SKILL.md` (between markdown code fences via awk) and replaces the section in `CLAUDE.md` (or appends if absent), preserving everything else. Step 7 stamps `.claude/llm-code-wiki.version` with upstream version and prints a summary including the manual-review list. Idempotent — same-version re-run exits at Step 1 with "Already up-to-date".
