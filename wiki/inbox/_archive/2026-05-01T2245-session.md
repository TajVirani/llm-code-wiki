@ FUNCTIONS::wiki-install-skill  •  .claude/skills/wiki-install/SKILL.md  •  #skill #install #bootstrap
Bootstraps the auto-wiki system as five Bash blocks with zero Write/Edit tool calls (down from ~20 mixed prompts). Block 1 verifies the .claude/ tree and materializes wiki/ scaffolding from shipped templates; Block 2 upserts both hooks into .claude/settings.json via a parametrized jq filter (idempotent remove-and-re-add); Block 3 appends the canonical CLAUDE.md section from templates/CLAUDE-MD-SECTION.md; Block 4 runs three smoke tests and stamps .claude/llm-code-wiki.version; Block 5 prints a per-step summary read from /tmp/lcw-install-status.txt. Aborts on missing required files with a re-run-remote-install pointer rather than falling back to inline content.

@ FUNCTIONS::wiki-update-skill  •  .claude/skills/wiki-update/SKILL.md  •  #skill #update #versioning

Step 6 reads the canonical section directly from the shipped .claude/skills/wiki-install/templates/CLAUDE-MD-SECTION.md template (single source of truth shared with /wiki-install Block 3) — replacing the earlier fragile awk-on-fenced-code-block extraction from wiki-install/SKILL.md.

@ ARCHITECTURE::install-template-files  •  .claude/skills/wiki-install/templates/  •  #install #templates #architecture
Two shipped scaffold-internal templates eliminate inline content generation in /wiki-install. CLAUDE-MD-SECTION.md holds the canonical "## Auto-maintained wiki" section as the single source of truth, consumed by both /wiki-install Block 3 (append) and /wiki-update Step 6 (replace-in-place). topic-index.seed.md holds the empty topic-index with `<<CREATED_TS>>` / `<<UPDATED_TS>>` placeholders that bash sed interpolates at install time — kept as a template rather than shipped to wiki/topic-index.md so per-install timestamps differ and the manifest's keep-policy doesn't have to negotiate user content. Both ship via dist-manifest.txt with default overwrite policy.

@ FUNCTIONS::wiki-curator-agent  •  .claude/agents/wiki-curator.md  •  #agent #curator #templates
Routes inbox entries and research-doc concepts into filed wiki notes per Rules.md. New Step 2c selects a specialized template from `wiki/_templates/` when one of six triggers fires (FSM, cross-file flow, decision branches, component boundary, orchestration with sub-flows, recurring pattern); otherwise falls back to `note.md`. Step 7 CREATE writes against the chosen template — all templates share the outer Summary/Tags/Created/Last Updated/Content/Related Notes schema; only the inside of `## Content` differs. Curator does not invent new templates; new triggers must amend Rules.md §12 in the same change as the template that supports them.
